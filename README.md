# ХАОЧИ — интернет-магазин китайских снеков

### [Открыть сайт → kuza-adidas.github.io/app](https://kuza-adidas.github.io/app/)

[Админ-панель](https://kuza-adidas.github.io/app/admin/) · демо-пароль: `haochi-demo-2026`

Это рабочий макет, а не боевой магазин: реквизиты условные, реальной оплаты и отправки писем нет.

## Что внутри

| Раздел | Что сделано |
|---|---|
| **Витрина** | Главная, каталог с фильтрами, поиском и сортировкой, 23 карточки товаров, корзина в выезжающей панели, оформление заказа |
| **Товары** | 23 позиции. Все упаковки нарисованы генератором (`scripts/gen-illustrations.mjs`) в едином стиле «стикер»: плоские цвета, контур тушью, жёсткая тень, иероглифы кистью. Любую картинку можно заменить фотографией в админке |
| **Админ-панель** (`/admin/`) | Статистика, товары (добавление, изменение, удаление, загрузка фото), заказы и их статусы, чат с клиентами, настройки сайта (контакты, плашка, порог бесплатной доставки) |
| **Чат поддержки** | Виджет на всех страницах. Бот сразу отвечает на частые вопросы, оператор отвечает из админки |
| **База данных** | SQLite на сервере (`npm start`). На GitHub Pages сервера нет, поэтому там данные хранятся в IndexedDB браузера (демо-режим). Код сайта одинаковый, режим выбирается автоматически |
| **Статистика** | Первый визит (дата, источник: UTM, Яндекс, Google, VK, Telegram, страница входа, устройство), просмотры, добавления в корзину, начало оформления, покупка. Отчёт «путь покупателя» показывает время от первого визита до покупки, плюс воронка, конверсия, выручка и популярные товары |
| **Согласия и документы** | Cookie-баннер (аналитика включается только после согласия), отдельные документы: политика обработки ПД, согласие на обработку ПД, согласие на рассылку, политика cookie, публичная оферта, доставка и возврат. Согласия при заказе фиксируются в журнале `consents` |
| **SEO** | Все страницы заранее собраны в HTML, у каждой свои title и description, есть canonical, Open Graph, JSON-LD (Product, BreadcrumbList, FAQPage, OnlineStore, WebSite), sitemap.xml и robots.txt, ЧПУ вида `/p/latiao-lobster.html` |
| **Скорость** | Без фреймворков, JS и CSS минифицированы, картинки в WebP с `srcset` и ленивой загрузкой, шрифты свои с предзагрузкой. Lighthouse (мобильный профиль): производительность 91–99, доступность, best practices и SEO по 100 |

**Дизайн: «ночной рынок» на газетной бумаге.** Растровая бумага, контуры тушью, жёсткие тени, рукописные ценники, вывески с иероглифами, бумажные фонари. Эмодзи на сайте нет, это проверяет автотест.

**Шрифты:**
- Unbounded — заголовки-вывески;
- Golos Text — основной текст;
- Neucha — ценники и пометки «от руки»;
- Ma Shan Zheng — иероглифы кистью;
- ZCOOL QingKe HuangYou — вывески категорий.

Китайские шрифты урезаны до используемых иероглифов (около 35 и 15 КБ), скрипт: `scripts/subset_cjk.py`.

**Анимации:**
- на главной иероглифы «прописываются» кистью, строки заголовка поднимаются, упаковки парят;
- фонари качаются, бейдж доставки вращается, бегущая строка останавливается при наведении;
- блоки появляются при прокрутке;
- товар «летит» в корзину при добавлении;
- на успешном заказе ставится печать;
- кнопки «вдавливаются» при нажатии.

Если в системе включено «уменьшение движения», анимации отключаются.

## Безопасность

- **XSS.** Данные выводятся только через `textContent`, `innerHTML` с пользовательскими данными нигде не используется. Строгая политика CSP без `unsafe-inline` (ни одного inline-скрипта или inline-стиля). Ссылки и картинки проходят белый список схем.
- **CSRF.** Cookie сессии `HttpOnly` + `SameSite=Strict`, CSRF-токен на все изменения в админке, проверка `Origin`, API принимает только `application/json`.
- **Подбор пароля.** Пароль хранится только как хеш scrypt, сравнение за постоянное время, после 5 неудачных попыток вход блокируется на 15 минут. Есть общий rate-limit по IP на API, заказы, чат и события.
- **Инъекции.** К SQLite ходят только параметризованные запросы. Сервер повторно проверяет все входные данные (общий модуль `validate.js`). Цены в заказе всегда берутся из базы: подменить цену с клиента нельзя, это покрыто тестом.
- **Загрузка файлов.** Проверяется сигнатура (PNG/JPEG/WebP), размер ограничен, имя файла случайное, файлы отдаются с `nosniff` и `CSP: sandbox`. HTML под видом PNG отклоняется.
- **Заголовки.** CSP, `X-Frame-Options: DENY`, `frame-ancestors 'none'`, HSTS (при HTTPS), `Referrer-Policy`, `Permissions-Policy`, COOP/CORP.
- **Прочее.** Защита от обхода каталогов, лимиты на размер тела и таймауты запросов (slowloris), ловушки для ботов в формах, IP хранится только как хеш, `admin/` закрыт от индексации.

**Важное ограничение демо-режима.** На GitHub Pages нет сервера, поэтому вход в админку там проверяется в браузере (хешем PBKDF2), а данные видны только в вашем браузере. Это витрина возможностей. Настоящая защита работает в серверном режиме (`npm start`), и боевой магазин нужно запускать именно так, за HTTPS.

## Запуск локально

Нужен Node.js 22.13 или новее (встроенный SQLite).

```bash
npm install
npm run build                            # собрать сайт в dist/
ADMIN_PASSWORD='ваш-пароль' npm start    # http://localhost:3000, админка /admin/
```

Переменные окружения: `PORT`, `HOST`, `ADMIN_PASSWORD`, `DB_FILE` (по умолчанию `data/shop.db`), `TRUST_PROXY=1` (за nginx), `NODE_ENV=production`, `SITE_URL` (для canonical и sitemap при сборке), `DEMO_ADMIN_PASSWORD` (пароль статического демо).

## Тесты

```bash
npm test          # 35 unit/интеграционных тестов: валидация, API, безопасность, SEO, сборка
npm run test:e2e  # 10 сквозных тестов в Chromium: покупка, чат, админка, мобильная версия
```

E2E-тесты прогоняются в двух режимах: с сервером и SQLite, и как на GitHub Pages (сайт под `/app/`, данные в IndexedDB). GitHub Actions запускает все тесты на каждый push и после этого публикует сайт.

## Публикация на GitHub Pages

Workflow `.github/workflows/pages.yml` сам собирает и публикует основную ветку. Если после первого push сайт не открылся, включите Pages один раз вручную: **Settings → Pages → Build and deployment → Source: GitHub Actions**, затем перезапустите workflow во вкладке Actions.

Чтобы ссылка на сайт была видна сразу при открытии репозитория, нажмите шестерёнку в блоке **About** справа и включите **Use your GitHub Pages website**. GitHub не умеет открывать сайт вместо страницы репозитория, поэтому ссылка также стоит первой строкой этого README.

## Структура

```
data/            products.json (каталог), site.json (контакты, реквизиты)
src/assets/      css, js (shop.js — витрина, admin.js — админка, lib/ — общий код), img, fonts
scripts/         build.mjs (сборка), templates.mjs, legal.mjs (документы),
                 gen-illustrations.mjs, gen-icons.mjs, subset_cjk.py
server/          server.mjs (HTTP + API), db.mjs (SQLite)
tests/unit, tests/e2e
```

## Перед запуском настоящего магазина

- Заменить демо-реквизиты в `data/site.json`, отдать документы на проверку юристу, подать уведомление в Роскомнадзор и разместить базу на сервере в РФ (ч. 5 ст. 18 152-ФЗ).
- Подключить эквайринг и онлайн-кассу (54-ФЗ) и отправку писем.
- Развернуть `npm start` за HTTPS-прокси (`TRUST_PROXY=1`, `NODE_ENV=production`, свой `ADMIN_PASSWORD`).
- Все шрифты (Unbounded, Golos Text, Neucha, Ma Shan Zheng, ZCOOL QingKe HuangYou) распространяются по лицензии SIL Open Font License.
